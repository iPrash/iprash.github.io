1. The core idea

Problem: many lines of business × geographies × products, each with its own underwriting process. Forcing them into one system of record (one big CRM/policy platform rollout) is slow and costly, because the processes truly differ.

Answer: same agents, different context. Build a shared registry of reusable agents. Inject the market context (rules, appetite, forms, regulation, authority limits) at runtime. The business keeps its process variation; the architecture does not multiply.

2. Reference layers

Cross-cutting (the platform): an agent development SDK plus a runtime. They provide identity, guardrails, observability and tracing, evals, cost metering, and model gateway and model choice. say "Platform gives the plumbing; my job is agent boundaries, orchestration and context design."

3. Background vs foreground

Re-imagine the process instead of dropping agents into the legacy one. Map every underwriting step, then sort each step into one of two lanes:

  • A human sits where there is authority, accountability, or ambiguity: binding, referral above authority, declining, and price sign-off.
  • The agent's output arrives pre-assembled with evidence, so the underwriter reviews it rather than researching it.
  • Comments from the human are captured. They feed evals and prompt or context improvement.

4. When should something be an agent?

✅ Make it an agent when the task needs…

  • Summarisation (a broker submission → a risk summary)
  • Extraction from unstructured docs (slip, schedules, loss runs)
  • Translation or normalisation across languages and formats
  • RAG over guidelines and wordings
  • Classification and triage, and reasoning that leads to a plan

❌ Keep it a tool or service when…

  • It is a deterministic API call (rate lookup, sanctions check, policy number)
  • Rules are fixed and auditable (authority limits → rules engine)
  • The math must be exact (pricing engine stays the pricing engine)

"An agent that only discovers and calls an API is just an expensive API client."

Design rules: one job per agent · explicit input and output contract (schema) · tools exposed through MCP · stateless agent, with state held in the orchestrator · every agent has evals and a version in the registry.

7. Fitting a base design to a specialty market (e.g. London / Lloyd's)

What is different

  • Broker-led placement; the slip / MRC is the core document
  • Lead and follow lines; subscription market with several syndicates on one risk
  • Delegated authority: coverholders, binders, bordereaux processing
  • Specialty classes (marine, energy, cyber, political risk) and heavy referral culture
  • Market data standards and modernisation (digital placement, core data record)

How I would run the fit (design SOW)

  1. Map the local process with the process engineers. Tag each step background or foreground.
  2. Gap-check against the agent registry. Mark each agent reuse / reconfigure / new.
  3. Build the market context pack: rules, appetite, authority, wordings, regulation.
  4. Pick the orchestration pattern for each journey.
  5. Define the human gates, evals and audit.
  6. Choose the lighthouse (MVP) use case, then plan the engineering.
Likely new agents: slip / MRC reader · bordereaux validation agent · lead/follow line comparison · broker correspondence drafter.

8. Governance and production readiness

Trust

  • Full trace per decision (inputs, tools called, model and version, output)
  • Explainability: cite the evidence behind every recommendation
  • Human owns the decision; the agent never binds on its own

Quality

  • Evals per agent, and golden sets from real submissions
  • Underwriter comments become eval cases
  • Regression tests on every prompt or model change

Control

  • Guardrails: PII, prompt injection from documents
  • Data residency (UK / EU), least-privilege tools
  • Cost and step budgets; caching; model routing

9. Lines to say

"Same agents, different context. We stop forcing the business to harmonise processes. We harmonise the agents and let context carry the variation."

"This is process re-imagination first. Background agents do the gathering and checking; the underwriter sits in the foreground making the decisions only a human should make."

"Not everything is an agent. If it's deterministic, it's a tool. Agents earn their place on summarisation, extraction, RAG and reasoning."

"I choose the simplest orchestration pattern that works and make every hop observable and evaluated."

"For a new market I'd map the process, gap it against the registry — reuse, reconfigure, new — build the context pack, and pick a lighthouse."
